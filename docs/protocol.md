# Локальный протокол desktop ↔ backend, v1

Привязка: `127.0.0.1`, HTTP и WebSocket. Launcher передаёт desktop путь к приватному JSON-файлу через `DECANAT_CONNECTION_FILE`. Его поля — `url` и случайный `token`; в query string токен не передаётся. Конфигурация с удалённым host не принимается desktop.

## Диалог

WebSocket `/v1/conversation`, заголовок `Authorization: Bearer <token>`. Разрешён один renderer-клиент на процесс. На подключении приходит снимок состояния; при разрыве сессия завершается и контекст очищается.

HTTP отклоняет любой `Origin`. Для WebSocket штатный UE 5.6 libwebsockets добавляет `Origin: http://127.0.0.1`; разрешено только это значение с loopback-host, `X-Decanat-Client: unreal-desktop` и правильным приватным bearer. Остальные origin отклоняются; отсутствие origin поддерживается для нативной диагностики. Это локальный IPC, не браузерный API.

Команды — JSON. После начала обязательно передавать `session_id`, полученный из события; для сообщений воспроизведения — также `turn_id`.

| `type` | Назначение и дополнительные поля |
| --- | --- |
| `start` | Начало разговора; session_id ещё не нужен |
| `avatar_ready` | Подтверждение завершения вставания/посадки, не готовности ответа |
| `face_ready` | Локальное лицо начало подготовленную анимацию; обязательны текущие `session_id` и `turn_id`. Поздний ACK не запускает следующую реплику |
| `finish` | Немедленное завершение сессии |
| `sources` | Показ текущих источников, считается активностью |
| `activity` | Действие пользователя, сбрасывающее таймер ожидания |
| `text` | Текстовая диагностика, поле `text`; не кнопка/поле студенческого UI |
| `speech_start` | Сигнал начала перебивания от внешнего аудиоклиента |
| `audio_end` | PCM16 little-endian mono в `audio_b64`, частота в `sample_rate`; до 45 секунд |
| `playback_progress` | `played_characters`, подтверждённый префикс завершённых речевых фрагментов |
| `playback_finished` | Подтверждение фактического окончания звука |

В основной локальной конфигурации захватом/воспроизведением управляет AudioDeviceAgent внутри backend, поэтому renderer не должен воспроизводить PCM или дублировать playback-progress. Сообщения аудиоклиента оставлены для независимых проверок/адаптеров, не для ввода студента с клавиатуры.

Событие имеет поля `sequence`, `kind`, `session_id`, `turn_id`, `payload`:

- `snapshot`: актуальные state/history/answer/sources. Поля `warning` и `warning_seconds` передают состояние предупреждения по тому же дедлайну, что и отдельное событие. Число секунд округляется вверх. При разрыве WS предыдущий диалог завершается, поэтому новый клиент получает пустую сессию.
- `state`: `idle`, `standing_up`, `listening`, `transcribing`, `thinking`, `speaking`, `sitting_down`.
- `avatar`: `action=stand|sit`; после реальной анимации renderer отвечает `avatar_ready`.
- `transcript`: распознанный вопрос в `text`.
- `turn_started`: начата обработка новой аудиореплики; убрать прежний текст и источники, не стирая каноническую историю текущего разговора.
- `answer`: структурированный ответ, подтверждающие фрагменты и имя фактически использованного провайдера.
- `speech`: подготовка мимики, PCM16 mono base64, sample_rate=48000, text, duration и `speech_marks` (`sample`, `characters`). Renderer передаёт PCM только локальному ACE с нулевой слышимой громкостью. Состояние остаётся `thinking`; аудиоустройство пока не воспроизводит запись.
- `playback_start`: после `face_ready` для ожидающей реплики backend переходит в `speaking` и передаёт ту же запись единственному слышимому AudioDeviceAgent. Renderer это событие повторно не озвучивает и не подаёт в ACE. Границы завершённых фрагментов подтверждаются после запланированного DAC-времени, а не пропорционально длительности. Незавершённый фрагмент при перебивании не считается подтверждённым целиком.
- `playback_stop`: немедленно сбросить звук и очереди мимики; ожидание остановки inference не задерживает эту команду.
- `sources`: исходные подтверждающие фрагменты, их название, происхождение и locator; внешние URL не открываются в системном браузере.
- `idle_warning`: `visible` и при показе `seconds`.
- `cleared`: очистить текст/источники студенческой сессии, `reason` — причина завершения.
- `error`, `command_error`, `clarify`: понятные русские сообщения; raw stderr, ключи и трассировки не отправляются студенту.
- `maintenance`, `knowledge_updated`: состояние обновления базы в даунтайме.
- `resync_required`: клиент отстал; соединение закрывается вместо бесконечного накопления событий.

Клиент не должен возобновлять старую реплику по задержанному callback. Окончание playback с другим turn_id игнорируется. Статусы генератора и JSON Schema находятся в `schemas/answer.schema.json`.

Ожидание лица ограничено `face_prepare_timeout` (по умолчанию 45 с). При тайм-ауте звук не запускается, разговор завершается с `face_timeout`, персонаж садится. При перебивании во время TTS/подготовки лица сгенерированный, но ещё не озвученный ответ сохраняется с пустым подтверждённым префиксом. На переходе из `speaking` в `listening` renderer останавливает и очищает мимику, а не удерживает последний кадр модели.

## Служебный доступ

Каждому служебному запросу нужен IPC bearer. Помимо него `/v1/admin/*`, кроме login, требует `X-Admin-Token`. В desktop-режиме сотрудник открывает вход сочетанием Ctrl+Alt+A. При первом входе `POST /v1/setup/password` принимает `{"password":"…"}` и отдельный `X-Setup-Token`. Launcher передаёт этот токен только процессам текущего запуска. Маршрут возвращает 403 без токена и 409 при уже существующем пароле. Проверка существования и запись хеша идут под одной блокировкой. Обычный `decanat serve` требует пароль, заданный через `decanat init`.

`/v1/health` сообщает `knowledge_ready`, `knowledge_error`, `models_ready`, `audio_device_ready` и `restart_required`. В desktop-режиме `setup_step` показывает первое незавершённое действие: `password`, `knowledge`, `provider`, `models`, `devices` или `ready`. `setup_issue` содержит пояснение для сотрудника. Студенческий `start` требует `ready` на backend и `avatar_configured: true` от клиента с настроенным MetaHuman и локальным ACE. Это проверка конфигурации текущего запуска. После изменения речевых моделей или устройств новые разговоры блокируются до перезапуска.

`POST /v1/admin/knowledge/demo` явно устанавливает поставляемую вымышленную базу в пустой профиль. `demo_knowledge` выводит пометку на студенческом экране. Рабочая база устанавливается обычным ZIP-импортом. Для замены пакетом с другим `kb_id` сотрудник подтверждает `replace_kb=true`.

`POST /v1/admin/codex-login` открывает штатный вход ChatGPT в браузере. `POST /v1/admin/provider-check` отправляет выбранному провайдеру короткий вопрос с искусственным фактом и проверяет ответ со ссылкой на этот факт. Проверка исключает автоматический fallback и записи в журнале. Результат для выбранной конфигурации сохраняется в `provider-check.json` без паролей и ключей. Смена выбранного сервиса или модели требует новой проверки. Замена API-ключа для выбранного API также сбрасывает результат.

`GET /v1/admin/diagnostics` возвращает health, версии среды, наличие Codex, признак настройки API-ключа, метаданные базы и список PortAudio-устройств. Перечисление не запускает запись микрофона и проигрывание. Устройство выбирается по `audio.devices[].selection`, а `selectable_input` и `selectable_output` отмечают доступные для однозначного выбора устройства. Пустое поле сохраняет системный выбор. Если название и драйвер двух устройств совпадают, нужное устройство можно выбрать в Windows.

`POST /v1/admin/audio-test/input` измеряет пиковый уровень входа за три секунды. `POST /v1/admin/audio-test/output` синтезирует короткую фразу и отправляет её в действующий выходной поток. Проверки доступны в даунтайме, пока применённая конфигурация звука готова. Они пользуются текущим аудиопотоком и не создают запись журнала. `POST /v1/admin/audio-test-cancel`, выход сотрудника и разрыв WS останавливают тест.

`GET /v1/admin/journal?limit=20&offset=0` возвращает `items` и `has_more`. При одинаковом времени записи упорядочены по `turn_id`. Записи старше 30 дней исключаются из выдачи. `sources` содержит исходные снимки источников, а `spoken_text` и `interrupted` отражают подтверждённую озвучку и перебивание.

Отмена клиентом HTTP-импорта после начала построения индекса не возвращает систему из обслуживания, пока поток изменения базы не завершён. Это сохраняет запрет на обновление фактов во время разговора даже при оборванном служебном запросе.
