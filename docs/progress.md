## Продолжение Windows — 2026-11-06

Собрана и запущена отдельная от редактора **Win64 Development с ACE**. На RTX 3080 работает `LocalA2F-Mark`, без облачного provider мимики. Собственный `ABP_DecanatFace` использует явный Body source, моргание, ACE-кривые и собственный ARKit mapping; исходные Epic-ассеты не изменены. В PIE проверены настоящие кривые и движение костей челюсти, завершение ответа, отмена и следующая реплика. Повторная проверка моргания: кривая **0.797**, смещение века относительно головы **0.894 см**.

В packaged build прошли **девять сценариев**: семь сценариев тела/IPC из предыдущего раздела, полная речь через настоящий аудиовыход и три ранние отмены до `face_ready`. Реальные native-подтверждения привязаны к ожидающей реплике. Подготовка лица больше не запускает слышимый звук: backend ждёт `face_ready`, затем отправляет `playback_start`. Отмена оставляет тело стоящим, возвращает челюсть к нейтральной позе и не возобновляет отменённую речь. Отчёт — `.runtime/unreal/packaged-cold-cancel-verification.json`.

Ранний прогон выявил настоящий deadlock: ACE callback удерживал registry lock и ожидал настройки компонента в игровом потоке, который в это время ожидал отмену. Теперь у каждой реплики отдельный `FDecanatFaceRequest`: он копирует данные SDK в очередь игрового потока, отбрасывает отменённые доставки и отсоединяется от registry в фоне. Отмена старой реплики не отсоединяет новую. Исправление проверено в новой упаковке. Отдельно исправлено преждевременное чтение тестом буферизованного native-журнала: проверка ждёт свежие отсчёты после остановки.

Для устройств Windows по умолчанию выбирается совместимый WASAPI с низкой задержкой; ручной выбор сотрудника сохраняется. На Realtek сравнивались часы мимики и PortAudio DAC timestamps, без открытия микрофона: **93 отсчёта, максимальное расхождение 83.8 мс, p95 83.3 мс** в последнем прогоне. Предыдущий прогон до доработки отмены дал 26–42 мс; MME давал 101–136 мс. Это компонентные замеры на данном ПК, не гарантия для любых устройств и не акустическая приёмка микрофона.

Проверки доступных локальных моделей и hybrid retrieval пройдены в указанном диагностическом объёме. На Windows уже подготовлены Unreal/MetaHuman, деловой образ и четыре движения, собраны редакторский и игровой targets без ACE. Внешность утверждена, F-01 завершён. Далее по очереди — F-02, полный цикл движений во всех сценариях сессии; затем F-03, локальный ACE и синхронизация. Кандидат стека и недостающие компоненты записаны в `docs/target-environment.md` и `assets/manifest/desktop-stack.json`. Вход Epic подтверждён; архивы NVIDIA и локальные веса пока не получены, их ссылки требуют Developer login.

Обновление подготовки стенда: пользователь предложил Windows-ноутбук с Core i5 / мобильной RTX 2050 и готов организовать аккаунты/удалённый доступ. Составлено `docs/windows-testhost-checklist.md`: RustDesk-сеанс с Mac, затем проверка управления и настройка SSH; входы Epic/NVIDIA/Codex выполняет владелец. Доступ ещё не подключён. У RTX 2050 стандартно 4 GB VRAM, поэтому пригодность для выбранной diffusion-мимики не подтверждена; экономный локальный provider и общая сцена требуют отдельного теста.

При повторном запуске Whisper с GPU по умолчанию обнаружен нативный сбой выделения Metal-буфера в ограниченной macOS-среде. Режим ASR теперь выбирается явно: CPU по умолчанию, `whisper_use_gpu=true` только после проверки конкретного backend/устройства. CPU-прогон прошёл. Отмена ASR передаётся в штатный native abort callback; отменённый TTS прекращает работу между фрагментами.

Дополнительно исправлены: превышение лимита 45 с из-за округления VAD; склейка аудио после переполнения очереди; перенос захваченных кадров в новый сеанс; запоздалая отправка старого вопроса следующему студенту; отложенная очистка уже нового диалога; повторные обращения к заведомо исчерпанному Codex при включённом fallback. Временный rate limit отличается от исчерпанной квоты. Неразобранная реплика вызывает локальную голосовую просьбу повторить, без LLM-запроса; отсутствие фактов само по себе не вызывает лишней просьбы уточнить. В C++ добавлены локальный allowlist provider-ов и StopCharacter, но их реальная компиляция/очистка буферов остаётся целевой проверкой.

Отмена HTTP-загрузки базы больше не снимает обслуживание, пока нативный поток ещё строит индекс. Завершение атомарного импорта дожидается фактически, затем актуализируется готовность и только после этого разрешаются новые разговоры; сценарий проверен отдельным тестом.
