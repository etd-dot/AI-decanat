# Подключение настоящего Unreal/MetaHuman-аватара

Статус на 2026-11-06: **реально собраны редакторский и игровой Win64-targets и packaged build с ACE на UE 5.6.1**. В `/Game/Decanat/Office` установлен настоящий `BP_DeanOffice` с деловой одеждой, четырьмя движениями и собственным лицевым графом. Внешность и голос утверждены пользователем. Девять runtime-сценариев проходят, измерены часы лица и настоящего WASAPI-аудиовыхода. Пользователь подтвердил живой голосовой вопрос и озвученный ответ в пробном приложении. Полная приёмка продукта и право production-поставки старых моделей остаются открытыми. Команды и границы проверок — [avatar-authoring.md](avatar-authoring.md); среда — [windows-environment.md](windows-environment.md).

Проверенный стенд — UE 5.6.1 / официальный ACE archive 2.5.0rc3 / локальный Mark 3.0. Версии и SHA — `assets/manifest/ace-runtime.json`. Это проверенный Development-комплект, не принятый production-релиз; лицензионные различия старого и открытого выпусков описаны в [third-party.md](third-party.md).

## Перед сборкой

После подтверждённого входа Epic продолжать подготовку без дополнительного окна Character Asset:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File tools/unreal.ps1 -Action AssembleCharacter -NoHttpConnectionReuse -EditorCoreLimit 4
```

На этом ПК файл подкачки увеличен пользователем: активны 16 GiB, максимум 32 GiB. Это позволило завершить импорт полного лицевого рига, который раньше падал при выделении ещё 2340.2 MiB. `-NoHttpConnectionReuse` передаёт штатный `-noreuseconn` для выявленного TLS-сбоя; проверка сертификатов включена. После появления texture sources скрипт ждёт окончания их обработки. Вызов сборки явно передаёт штатный **UE Optimized / High** pipeline (`BP_DefaultLegacyPipeline_High`), создающий отдельный runtime actor с Body/Face. Callback UE 5.6.1 обращается к pipeline без проверки на null, несмотря на объявленную необязательность параметра. Внутренний pipeline исходного Character нельзя просто передать внешней сохраняемой коллекции: это приводит к запрещённой ссылке на private object.

Для технического кадра собранного `BP_Decanat` предусмотрено действие `-Action PreviewCharacter`. Оно загружает настоящую карту Office, создаёт актор и проверяет его Body, пишет `.runtime/unreal/metahuman-runtime.json` и `metahuman-preview.png`. Изменения карты при этом не сохраняются; результат не означает проверки четырёх движений, ACE или утверждения внешности.

Технический кадр уже получен и просмотрен. Действие `-Action BindCharacter` также выполнено: настоящий Blueprint сохранён в Character Asset актора основной карты, `AvatarClass` заполнен. Повторная привязка не заменяет другой ранее назначенный персонаж и не сбрасывает отредактированную позицию уже привязанного актора. Анимационные поля пока пусты; это сохраняет отказ готовности до подготовки полного набора движений и локального face provider.

На Windows сначала выполнить `powershell -NoProfile -ExecutionPolicy Bypass -File tools/unreal.ps1 -Action Check`. Команда с `-Action Build` собирает редакторский модуль без ACE; `-Action CreateScene` после сборки запускает генератор карты. Эти действия уже выполнены на настоящем UE 5.6.1; повторное создание существующей карты запрещено. `-Action PrepareCharacter` подготавливает редактируемый MetaHuman, `-Action AssembleCharacter` запускает риг/текстуры/assembly, `-Action Render` делает настоящий рендер из камеры сцены. Последние действия проверяются отдельно по журналам. Нестандартный каталог задаётся через `-EngineRoot`. Результаты записываются в `.runtime/unreal/`. Для MetaHuman нужна опция **MetaHuman Creator Core Data**, а в проекте включён плагин MetaHuman Creator (`MetaHumanCharacter`). UE 5.8 не подставлять вместо 5.6: совместимость текущего ACE-кандидата с ним не подтверждена.

1. Выбрать и установить совместимые Unreal Engine, MetaHuman и NVIDIA ACE local execution plugin, сверив матрицу плагина. Проверить бесплатность выбранного образовательного использования и правила распространения. Не брать несовместимые последние версии независимо друг от друга.
2. Открыть `desktop/Decanat/Decanat.uproject`, собрать C++-модуль сначала без ACE и устранить ошибки на реальной версии UE. Потребуются штатные средства разработки UE для целевой ОС.
3. На Windows установить plugin `NV_ACE_Reference` и локальный provider вместе с его весами, включить установленные плагины в проекте. Собрать с переменной `DECANAT_WITH_ACE=1`. На macOS CUDA-провайдер не подменяется облачным.
4. Создать вымышленного MetaHuman, кабинет с фиксированным ракурсом и четыре анимации: сидячий idle, вставание, стоячий idle, посадка. Готовые бесплатные анимации допустимы только при подходящей лицензии; иначе подготовить свои. Полный риг/движение не заменяется картинкой человека.

## Карта и конфигурация

`tools/create_unreal_scene.py` выполняется через Unreal Editor и создаёт настоящую карту `/Game/Decanat/Office` со своими простыми предметами и камерой. Скрипт не перезаписывает существующую карту. Он не генерирует MetaHuman автоматически и не создаёт фиктивные бинарные ассеты.

Генератор создаёт собственные материалы, стол, стул с опорами, ноутбук с экраном и клавиатурой, бумаги, фон, фиксированную камеру 16:9 и три источника света. Готовые материалы повторно используются без перезаписи. Наличие C++-класса, базового mesh и корректность указанных в конфигурации ассетов проверяются до смены открытой карты. Сам внешний вид ещё требует рендера и приёмки в движке.

В `[Decanat]` файла DefaultGame.ini указать:

- `AvatarClass`: путь к настоящему Blueprint generated class персонажа;
- `SitIdleAnimation`, `StandAnimation`, `StandIdleAnimation`, `SitAnimation`: совместимые с Body SkeletalMesh animation sequence assets;
- `SpeakingIdleAnimation`: необязательная совместимая зацикленная анимация жестов при речи; если не задана, используется `StandIdleAnimation`;
- `LocalFaceProvider`: фактическое имя из разрешённого локального списка `LocalA2F-Mark|James|Claire` или их `-AR` вариантов. Имя дополнительно сверяется с перечислением реально доступных provider-ов. `Default`, `RemoteA2F`, `LegacyA2F` не принимаются.

Если эти пути заполнены до создания карты, генератор сохраняет персонажа в `Character Asset`, а анимации — в `Animation Assets` размещённого актора аватара. Эти сериализованные ссылки нужны cooker-у: строки в INI сами по себе не гарантируют включения ассетов в packaged build. Если карта уже создана, назначить эти поля в Details актора, используя имена ключей выше для Animation Assets, и сохранить карту. Пустые настройки позволяют создать только кабинет с предупреждением об отсутствующем персонаже; готовность аватара при этом не выставляется.

Runtime проверяет наличие Body, длительность и совместимость скелетов анимаций. При наличии тела и анимаций сидячая поза отображается и в сборке без ACE, чтобы можно было проверить сцену; студенческий диалог остаётся недоступным до подключения полного комплекта. Вставание/посадка подтверждаются по позиции воспроизведения AnimSequence, а не по истечению таймера; при смене сессии старое подтверждение не отправляется. Реальные движения, контакты и отсутствие скачков при смене клипов проверяются отдельно в движке.

Используемые интерфейсы: [MaterialEditingLibrary UE 5.6](https://dev.epicgames.com/documentation/en-us/unreal-engine/python-api/class/MaterialEditingLibrary?application_version=5.6), [UAnimSingleNodeInstance](https://dev.epicgames.com/documentation/en-us/unreal-engine/API/Runtime/Engine/UAnimSingleNodeInstance). Сверка документации не заменяет компиляцию на конкретной версии UE.

У MetaHuman должен быть компонент `Body`; на лице настроить ACE Audio Curve Source и применение ACE Face Animations в face animation graph по документации выбранного плагина. Проверить MouthClose/retarget-настройки именно данной версии MetaHuman. Собственную слышимую озвучку ACE отключить: воспроизведением владеет backend. При этом компонент должен продолжать выдавать кривые; это проверяется в packaged build.

## Проверки перед признанием интеграции готовой

- Реальный Windows packaged build, а не только Play in Editor.
- Начало разговора сразу запускает вставание; голос студента во время перехода не теряется.
- Посадка при завершении, тайм-ауте и ошибке лимита; новые вопросы не запускаются во время посадки.
- Локальная мимика на русском PCM; отсутствие запросов в облачный сервис аватара.
- Нет двойного голоса. Звук и лицо синхронны с учётом буферизации ACE; при необходимости добавить явное подтверждение готовности лица перед стартом аудио.
- При перебивании прекращаются звук и накопленная лицевая анимация; поздний callback отменённой inference-сессии не возобновляет рот.
- Все четыре body-анимации существуют и согласованы с посадкой за конкретный стол/стул. Не выставлять готовность по одной успешно загруженной модели.
- Кнопки начала/завершения/источников, предупреждение бездействия и очистка предыдущего студента.
- Настройки сотрудника открываются сочетанием Ctrl+Alt+A только вне диалога, затем требуют пароль. Сочетание — способ открыть форму, а не механизм авторизации.

Движения, локальная генерация, моргание, один слышимый output, `face_ready` и отмена до/после начала речи уже проверены в настоящей сборке; детали — [progress.md](progress.md). Ещё открыты акустическое качество AEC, расширенная речь, полный студенческий/служебный сценарий, чистая установка и длительный прогон. После изменений повторять затронутые проверки на фактических версиях пакетов.

## Киоск

Выделить ограниченную учётную запись Windows и настроить подходящие выбранной редакции ОС средства киоск/оболочки и блокировки системных действий. Launcher запускает desktop в fullscreen, но это не заменяет политику ОС. Предусмотреть отдельный доступ сотрудника для обслуживания и выхода из киоска. Физическое встраивание в терминал в задачу не входит.
